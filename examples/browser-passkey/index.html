soroauth — sign and submit a Soroban transfer with a passkey

The browser builds a native-XLM SAC transfer from the wallet contract, derives the payload from the record-mode simulation with the @soroauth/wasm core, signs it with a passkey as the WebAuthn challenge, re-simulates in enforce mode, submits, and prints the transaction hash and an explorer link. Nothing is asked of a server until the signed entry exists. See README.md in this directory.

Paying for and submitting the transaction

A contract account cannot be a transaction source, so somebody else pays the fee. Set a relayer URL to keep every secret out of this page, or paste a throwaway TESTNET fee-payer secret to submit directly. The secret is kept in memory for this one call and is never stored or logged.
